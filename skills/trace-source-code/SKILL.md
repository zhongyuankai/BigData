# Trace Source Code

跟踪真实源码，用具体案例讲清执行过程，生成易读文档，并完成索引、提交与推送。只分析，不修改被跟踪的实现；用户明确指定的范围和交付方式优先。

## 源码跟踪

1. 明确分析目标与边界；目标不清时先澄清，大型子系统先确认拆分方案。
2. 沿入口追踪调用链、核心分支、状态与数据变化、副作用、异常边界及相关测试，以直接源码证据支撑结论。
3. 用一个具体输入或状态贯穿分析，按真实执行顺序解释每一步“从哪里来、做什么、改变什么、为什么、到哪里去”。证据不足时明确标注，不按名称或惯例猜测。

## 文档表达

- 中文说明，代码标识和日志保留原文并用行内代码标注。先讲问题与整体流程，再展开关键实现，最后给出简短心智模型和源码阅读顺序。
- 关键结论标注 `源码文件:行号`，不生成源码 Markdown 链接；只摘录必要的短代码，并结合数值、状态表或输入输出解释。复杂状态、异步或多组件协作才使用 Mermaid。
- 区分事实、推断和待验证项；疑似缺陷、注释不一致或并发风险集中放入“源码审阅发现”。按目标裁剪内容，不堆砌源码或无关章节。
- 不记录仓库名、分支、提交 SHA 或生成日期。

## 输出与索引

- 默认根目录：`/Users/didi/zyk/doc/github/BigData`。先读 README 和现有目录，按主题归类，如 `ElasticSearch/`、`Kafka/`、`Java/Thread/`、`Java/Jvm/`；无合适目录再创建，不静默回退到源码仓库。
- 同目标、同范围的已有文档优先原地更新并保留旧文件名。新文件使用小写连字符主题名，如 `replication-tracker.md`，不加 `source-trace` 或编号；用户指定路径或文件名时遵从。
- 同步项目根 `README.md`：在对应主题章节维护唯一条目，使用有效相对链接，重命名时同步修正；缺少章节或 README 时按现有风格补建，不整理无关条目。空格路径用尖括号或 URL 编码。
- 指定其他输出位置时，项目根取目标 Git 仓库根；非 Git 目录取用户指定的文档目录。用户限定只输出单文件时，只写该文件，跳过索引、提交和推送。

## 验证与发布

1. 核对源码位置、代码片段、事实边界、案例、代码围栏、Markdown 空白及本次 README 链接；文档任务不默认运行大型构建或测试。
2. 在文档仓库检查指南、分支、远端、上游和工作区状态，审阅本次 diff。只提交本次文件和差异，保留无关暂存及未暂存改动；同文件已有改动也需隔离，用户明确纳入整文件时除外。可用 `git commit --only -- <本次文件>` 限定路径。
3. 默认创建概括主题的 commit，推送到已配置的对应远端分支，并核实远端包含该提交。无变更时跳过提交和推送；仅重试已确认属于本任务的失败推送。遵从用户不提交、不推送等明确要求。
4. 待推送范围含无关提交、无法隔离改动、目录不可访问、缺少可用 Git 仓库/分支/远端，以及鉴权或推送失败时，保留成果并报告阻塞；不自动初始化仓库、搬运提交、重写历史或强推。
5. 最终报告文档路径、README 更新、commit 和推送结果；未完成步骤如实说明。
